# Experimental draft review — English documentation only

When `draft_response` is present, treat it as a proposed answer, not an established
fact. Check whether it resolves the whole question using actual readings. Choose
`open` or `search` if a required condition is missing or an unread chapter supplies
a necessary detail. Otherwise choose `answer` with a complete response. Do not
change a correct answer merely because it was reviewed. No answer key is supplied.

The prototype requests one extra model review of the first proposed answer per
fresh session. It does not force any search, select node IDs or block final answers.
It is not enabled in Luca's application runtime.
